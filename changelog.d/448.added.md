- **`vitai classify-pending <dataset>`** (#448): the CLI harness over
  `Vitai.classify_pending`, which #425 shipped as an API-only read surface.
  P9 says a capability ships as BOTH a command and a `vitai.api` method, and
  an importer that spools an export and appends it is exactly the caller that
  runs from a shell. Reads JSONL on stdin - the same rows `vitai append`
  takes, through the same reader - and prints a verdict per row, `--json` for
  the API's dicts verbatim.
- **The refusal sentences print by default, under the table.** A `refused`
  row's `reason` is the sentence `append_many` would raise with, which is what
  `pending_problems` returns, so the sentences are reachable without a second
  command. They print beneath the verdicts keyed by row rather than in a
  column: a verdict is a word and a reason is a paragraph. One sentence covers
  every row naming the same reference, printed once and labelled with the rows
  it is about rather than repeated per row.
- **A refused batch exits 2** - the status `may` and `safety` already use for
  "the answer is no" - so `vitai classify-pending daily < day.jsonl && vitai
  append daily < day.jsonl` is the shell sentence, and no script has to parse
  JSON to decide. The append is all-or-nothing, so the summary says no row
  would land rather than leaving a reader to infer it from one word in a table.
- Nothing is written. `--json` still emits every row before the non-zero exit:
  the status is for the shell, the rows are for the consumer.
