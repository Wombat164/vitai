- **The boundary gate now catches bare clinical category words** (#379).
  `scripts/boundary_gate.py` previously enforced only care-seeking directives
  and a purpose verb next to a medical noun, so a sentence like "your BMI
  entered the healthy range" passed untouched - no purpose verb, no matching
  noun. A new `CATEGORY_WORDS` deny list (`overweight`, `obese`, `underweight`,
  `healthy weight`, `healthy range`, `normal range`, `ideal weight`,
  `hypertensive`, `prehypertension`) closes that gap, checked against the
  whole repository for false positives before landing.
- **The gate's own docstring now says what it does not cover.** `CATEGORY_WORDS`
  is a deny list, not a definition of class (c): it catches the category
  words that were thought of and nothing else, and the rest of
  `docs/medical-boundary.md`'s class (c) is still enforced only by review.
  This is the durable half of the change - the word list will rot, the
  admission will not.
- **A hyphenated spelling of `overweight`, `underweight` or `prehypertension`
  is caught.** `_match_form` turns a hyphen into a space, which is the right
  transform for a multi-word phrase already on the list but left these three
  fused compounds unmatched in either spelling variant - "over-weight" and
  "pre-hypertension" (the more common clinical spelling of the two) passed
  clean. `findings()` now also checks a hyphen-removed form for the category
  family.
- **`ideal weight`, `healthy range` and `normal range` now require a nearby
  body-composition noun (`bmi`, `weight`, `body fat`, `kg`, `mass`, `waist`)
  to fire.** All three are ordinary technical idioms outside this domain - a
  barbell has an "ideal weight" for a lift, a float-precision test passes in
  a "healthy range" of tolerance, a CSV column is named `normal_range` - and
  bare matching fired on each of those, none of which is a claim about a
  person. Scoped the way `_PURPOSE_RE` already scopes `PURPOSE_VERB` to
  `MEDICAL_NOUN`. The motivating example ("your BMI entered the healthy
  range") still fires.
- **A markdown-formatted code identifier no longer reads as prose for the
  category family.** `_MARKUP_RE` strips `_` as an emphasis marker, which
  turned `` `is_overweight_flag` `` into three separate words and fired on a
  variable name rather than a claim about a person - the exact shape a
  #370 BMI-band schema field will plausibly take. Category matching now runs
  against a second, underscore-preserving sentence form
  (`_MARKUP_RE_TIGHT` / `_tight_sentences()`) as well, scoped to the category
  family only so DIRECTIVES and the purpose-verb family still fold away
  underscore-based markdown emphasis (`_see a doctor_`) as before.
- **Correction:** the original PR claimed this fires on all five category
  phrasings it was verified against. That was not true of a hyphenated
  spelling of a word already on the list, which is the first of the fixes
  above.
