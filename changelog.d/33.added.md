- A `comparability` dataset: whether two instruments' readings of one field
  may be read as one series, EARNED BY OVERLAP and never asserted (#33 item
  2, #171 section 4.1). The default is NOT COMPARABLE - deriving a trend
  across a source change needs an explicit statement that the two sides are
  on the same footing, never an assumption because both are called weight.
- `vitai comparability`, `Vitai.comparability(field, origin_a, origin_b, on)`
  and the matching agent tool answer the question. Never `None`: silence
  resolves to a synthesised `not_comparable` row, a value in the vocabulary
  rather than a null a caller has to interpret. The resolver is
  ORDER-INSENSITIVE in the pair - asking about `(a, b)` answers exactly as
  `(b, a)` would - even though the identity stored on a row is not.
- Keyed on `origin_a`/`origin_b`, the same identity `capabilities` already
  uses for an instrument - not "system", which the original proposal used
  before this engine had settled what to call that identity. `basis` is
  `overlap` and only `overlap`, closed to one value, because the whole point
  is that comparability cannot be asserted from a datasheet, a vendor figure
  or an athlete's say-so.
- Three statuses: `comparable`, `offset`, `not_comparable`. `bias` and
  `spread` are both required beside `offset` (an offset with no measured
  size is the assertion this dataset exists to refuse, and a size with no
  reported spread is a number with no idea how firm it is) and both
  forbidden beside `not_comparable` (a number on a refusal is a number about
  nothing). Beside `comparable` the two are not symmetric: `bias` is
  forbidden there too (a measured bias means the pair is `offset`, not on
  the same footing), while `spread` is permitted (it says how tightly the
  two agreed over the overlap, which is meaningful evidence rather than a
  contradiction). `overlap_ref` is required beside `comparable` and
  `offset`; a stated `not_comparable` row is a bare refusal, not silence,
  and needs no `overlap_ref` to assert - a negative earns nothing.
- `offset` does NOT license a spanning derivation. It records that a
  cross-instrument difference was measured and how big it was; applying that
  number to a reading would be fabricating a measurement (P4). The
  weight-rate instrument-seam refusal (#33 item 3) lifts only when every
  instrument pair behind the window resolves to `comparable`, in both
  `vitai.verdicts.compute_verdicts` and the weekly rollup in `vitai.report`.
- The shipped demo carries a `comparable` declaration for `scale` vs `dexa`
  on `kg`, so the dataset ships exercised rather than empty.
