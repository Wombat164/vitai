- **Everything the `demo` CI job asserts now runs in pytest** (#389). The
  persona corpus is held to its generator inside the suite; the demo's
  equivalent lived only in `.github/workflows/ci.yml`, along with fourteen
  assertions about what the shipped example must actually say. A green local
  run could ship demo drift, and did: #370's contract bump moved the
  `contract` stamp on the demo's `emissions` rows, the local suite reported
  2908 passed, and the job went red on a push.
- Five of those assertions had no pytest equivalent against the demo at all -
  the happy-path verdict, the live gate in the rollup, and all three
  precondition states, including the one that matters most, that a check
  nobody did is not a pass.
- Written as assertions rather than greps, which is the other half. `grep -q
  "impact blocked"` says a string is present and cannot say what should have
  been there instead, so a failing job prints an exit code and sends the
  reader to the YAML. Each test carries what it protects. Built into a scratch
  copy rather than in place, so a test never writes `derived/` into the
  working tree and the demo is proved to build from its committed data alone.
- Driven through the CLI wherever the job used the CLI. #398 shipped a
  `KeyError` in a CLI renderer while the whole suite was green, because every
  test drove the API and nothing drove the command.
