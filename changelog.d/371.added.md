- `validate()` now catches an unpinned `weight` or `measurements` row rather
  than only leaving `protocol` readable and unread: where a dataset's own
  rows have named a protocol slug, every row of that dataset dated on or
  after that slug's earliest declaration and carrying no `protocol` is now an
  advisory, aggregated into one line naming the count and the date span
  rather than one line per row. A dataset that has never named a protocol
  stays silent - a `protocols` row does not say which dataset it governs, so
  "a protocol applies here" is derived from the dataset's own usage, never
  assumed from the mere existence of a `protocols` row for something else.
  Advisory, never a refusal: the file is append-only, most weight rows in a
  real record predate the practice, and a validator that cannot pass on a
  real record gets switched off (#371).
- Follow-up fixes to the advisory above, from review: the scope anchor is now
  the dataset's OWN adoption date - the earliest date one of its own rows
  named a real, declared protocol slug - rather than the earliest declaration
  date among every slug it has ever named, which could be pulled back years
  by an unrelated slug declared for something else. A slug this dataset names
  but that has no matching `protocols` row anywhere in the record is treated
  as a dangling reference: it does not anchor the scope and does not, on its
  own, turn the advisory on. The message no longer names a "(first: line N)"
  pointer, which was ambiguous once a dataset's rows span more than one
  device file (#105) and could point at a row that is not the one being
  reported; the date span already reported is unambiguous across files and
  is what a reader actually searches for.
