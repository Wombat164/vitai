- The medical-boundary gate scans everything and exempts by name, instead of
  looking only where a list told it to. `SURFACE` was an allowlist of places to
  LOOK, so every directory added to the repo was outside the gate until somebody
  remembered - which is how `tests/` stayed unscanned for the life of the project
  (#388). Measured before inverting: 67 tracked files with a scannable suffix
  were outside, in `changelog.d/` (45), `.github/` (8), `scripts/` (7),
  `CHANGELOG.md`, `CLAUDE.md`, `CODE_OF_CONDUCT.md`, `RELEASING.md`,
  `connectors/` and the requirements files. All of them published: the repo is
  public. 360 files scanned before, 422 after.
- `NOT_SCANNED` names what stays out, each with the reason, and what is named is
  not prose: the object store, third-party code in `.venv`, caches, packaging
  metadata absent from a fresh clone, and the built demo under
  `examples/demo/derived` - which would otherwise make the gate's answer depend
  on whether somebody had run a build.
- The gate does not read its own source, and that is a rule rather than an entry
  in the register, because it is not a decision anybody may extend to a second
  file. This file IS the deny list: scanned whole it reports 23 findings, 20 of
  which survive the use/mention split, because the doctrine explaining each word
  is a comment rather than a literal. Twenty per-sentence exemptions
  transcribing the gate's own deny list would not be review. Its TESTS are not
  spared - `tests/test_boundary_gate.py` carries fourteen per-sentence entries.
- Fifteen sentences in `CHANGELOG.md` and two changelog fragments are registered
  per sentence, each naming what it quotes. A project cannot say what it changed
  about a deny list without quoting the list, which is the shape the doctrine
  document's own five exemptions already have. One cost is recorded with them: a
  fragment's exemption migrates into `CHANGELOG.md` when
  `changelog_gate.py --assemble` runs, so the entry has to be re-keyed at
  release - and the staleness control is what will say so.
- Held by a test that asks git what it tracks and requires every scannable file
  to be scanned or named. The gate itself does not shell out: a gate that does
  will not run in a source tarball, so the walk is a walk and the test is where
  git is asked.
