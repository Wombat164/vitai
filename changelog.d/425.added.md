- **`Vitai.classify_pending(name, records)`, and `jsonl.classify_pending`
  under it** (#425): what the append would make of each row it has not written
  yet. One dict per row - `row`, `verdict`, `target`, `reason` - where the
  verdict is one of `jsonl.PENDING_VERDICTS`: `new`, `restatement`,
  `correction`, `unmatched`, `refused`.
- No clock is consulted to classify. Whether a row is a correction is read off
  `supersedes`, which its author wrote, and off whether the record holds the
  row it names. `recorded_at` decides only whether a declared correction would
  APPLY, which is an ordering question and is asked of the same guard the
  append asks.
- **An undeclared restatement comes back `restatement`, not `correction`**, and
  that is the answer rather than a shortfall in it. An importer re-exporting a
  day it already sent holds a row that restates one the record has, and the only
  orderable fact that could make it a correction is a timestamp it may not
  author. So the engine says what the row IS - a second claim, both live,
  resolution picks the later - and names the field that would change it. A
  correction is declared here; it is never inferred from a clock.
- Nothing is written and no stored row comes back: a row number, a verdict word,
  the reference the author supplied, and prose about ordering. The pending rows
  are stamped in memory to answer the ordering half and no file is opened for
  writing.
