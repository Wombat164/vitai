  byte-compares the demo against its generator, so it cannot drift - but
  nothing checked whether the generator had heard of a dataset at all. Adding
  one and writing its demo file by hand produced drift on a file nothing could
  regenerate, under a message advising exactly the fix that does not work.
- `generate_demo.py` now DECLARES what it writes, and asserts its own writer
  loop matches that register. The check reads the register rather than deriving
  the answer: a first attempt substring-matched the generator's source, which
  reported a dataset as written if its name appeared in a comment, was already
  armed by an unrelated `("equipment",` tuple sitting in that file, and went red
  on a refactor that changed nothing.
- Every dataset is either written or listed as deliberately absent with a
  reason, and the register has back-pressure in every direction: an entry that
  gains a writer must leave, one naming a dataset the schema no longer has must
  go, two entries may not share a reason, and a reason must name the dataset it
  is about - which is the check that caught a stale explanation claiming the
  demo's weigh-ins name a protocol slug when no demo row sets `protocol` at all.
- The orphan check covers the whole demo tree and the same file types `--check`
  compares, not just `data/*.jsonl`. A hand-written track under `tracks/` walked
  past the first version, and that is the directory where the personal gate
  permits coordinates ON THE GROUNDS that they are the generator's own output.
