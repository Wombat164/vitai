- **The population register measures reading, not name-appearance** (#412).
  Its "read" check asked whether a field's name occurred as a quoted string in
  any module except `schema.py` and `db.py`, so a docstring satisfied it, and
  so did an error message, a `--flag`, an MCP tool schema, a validation
  allowlist - and the module that WRITES the field, which names the key in
  order to store it. A field could be added, declared, written by the engine
  and consumed by nobody with the register green, which is the exact class it
  exists to catch. A read is now a LOAD out of a mapping, direct or through a
  name table that reaches a lookup; the writer is defined by role rather than
  by two filenames (the module that declares `KEYS`, the module that projects
  the record into SQLite, and any module that reaches `append` and stores the
  key), and a writer's load of its own field is not counted. Fourteen fields
  stopped passing: eleven were `seq`, machine-stamped by `jsonl` and refused
  from callers by name, now classified as machinery beside `device`; the other
  three - `inferences.evidence`, `emissions.policy_asof` and `plans.tier` -
  have no consumer and are on the register with the reason. The measurement
  itself now has tests, written against sources this repo does not contain, so
  the shape that used to slip through is refused before anyone writes it.
