- **The engine described an audience it never checked** (#470). `AUDIENCE`
  said `report:` surfaces reach "reader of the report", while
  `_namespace_catalogue("report")` admits every public read on `Vitai`. So a
  surface no report renders resolved under it and was published to clients as
  reaching them through the report. The only declaration ever written in that
  namespace is one: `report:questions.kind` at contract 49 - the demo's
  `questions()` returns four rows and its rollup renders none of them.
- The catalogue was right and the sentence was wrong, so the sentence moved:
  the audience is now "caller of a published read". The prefix keeps its
  spelling because it is written into a published declaration and into
  clients' read-sets, and renaming it would break both to fix a description.
  **No contract bump**: the namespace set is unchanged, membership is
  unchanged, and no surface resolves differently - what changed is a sentence
  that was false.
- Two controls pin it. One asserts the discrepancy as a declared property, so
  the prefix cannot quietly start meaning the report again; the other asserts
  that every audience string names who COULD read a surface and never that
  anybody does, because the engine cannot check the second from this side.
