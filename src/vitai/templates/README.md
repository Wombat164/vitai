# health (vitai content repo)

Personal health, fitness and nutrition record. **Keep this repo PRIVATE.**

Built on [vitai](https://github.com/Wombat164/vitai): plain-text record,
deterministic engine, LLM coaching via skills.

## Files

| File | What it is | Changes |
|---|---|---|
| `profile.md` | Full snapshot: physiology, history, constraints, motivations | Slowly |
| `plan.md` | The working plan. Start at section 0, open actions | Often |
| `CLAUDE.md` | Operating instructions for an AI assistant picking this up | Rarely |
| `vitai.toml` | Your STARTING thresholds (rate phases, HR caps, floors, gates) | Rarely |
| `data/*.jsonl` | Append-only observations. **Never edit a line** - supersede it | Weekly |
| `data/goals.jsonl` | What you are aiming at, dated. Editing = appending | Rarely |
| `data/thresholds.jsonl` | Dated threshold changes, so past weeks keep their targets | Rarely |
| `data/achievements.jsonl` | Things worth keeping. Hand-logged, unlike milestones | Rarely |
| `derived/` | Generated by `vitai build`. Disposable, always rebuildable | On build |

## Goals, and why editing one is an append

A goal is data, not prose. To change one, append a new line with the same
`slug` - both lines stay, and the pair is the history: when you set it, when
you moved it, and why. That is what lets the record answer "what was I aiming
at three months ago" instead of only "what am I aiming at now".

It also means loosening a target today cannot turn last month's misses into
hits. Past weeks are judged against the targets that were in force then. The
engine does flag a loosening that lands right after a bad week - not as an
accusation, just as something worth a sentence in the `reason` field.

Each goal declares how events count toward it:

- `monotonic` - more always counts (steps, protein, reading minutes).
- `guarded` - volume beyond `guard_pct` above your recent baseline does NOT
  advance the goal. A 30 km week off a 12 km base is ramp rate you did not
  budget, and ramp rate is what injures people. The engine declines to credit
  it rather than congratulating you for it.

Run `vitai goals` to see where each one stands.

## Weekly, about 3 minutes

```bash
# append the week's lines to data/*.jsonl, then:
vitai validate && vitai build
git add -A && git commit -m "week of $(date +%Y-%m-%d)" && git push
```

Read `derived/weekly.md` for the rate check and tripwires.

## The three rules

1. **Never edit a `.jsonl` line.** Append a correction with `supersedes`.
2. **Never hand-edit `derived/`.** Delete and rebuild instead.
3. **Sparse and continuous beats rich and abandoned.** If the weekly cost
   exceeds three minutes, cut fields - do not skip weeks. If motivation dips
   to nothing, `weight.jsonl` alone still carries the primary goal.
